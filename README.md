# Модуль Google Merchant API для OkayCMS

Передає товари в Google Merchant Center через [Merchant API](https://developers.google.com/merchant/api)
замість XML-фіда, який Google забирає раз на добу. Ціна й наявність доходять до Google за ~15 хвилин,
а не наступного дня; статуси й проблеми товарів видно прямо в адмінці.

Дані беруться тим самим конвеєром, що й фід модуля `OkayCMS/GoogleMerchant`, тож усе, що в нього
додають інші модулі, потрапляє в API без змін.

## Можливості

- Товари обраних мов сайту — кожна мова окремим API-джерелом даних у Merchant Center.
- Лише зміни: модуль перебудовує товари й надсилає те, що змінилось.
  Наявність, дата відправки, ціна, акція, посилання й виключення з реклами — одразу;
  решта — не частіше разу на 12 годин; незмінні товари освіжаються раз на 20 днів
  (Google прибирає товар, який не оновлювався 30 днів).
- Товар, що зник із набору (прихований, без фото, без ціни, інша категорія), видаляється з Google.
  Якщо мало б зникнути понад 10 % товарів — видалення чекають підтвердження саме цієї кількості.
- Мітка цінового діапазону (`custom_label_0…4`) за межами з адмінки — замість правила атрибута в
  Merchant Center.
- Сухий прогін: план рахується й пишеться в журнал, у Google нічого не йде.
- Журнал запусків і щоденні статуси товарів (відхилені, обмежені — з поясненням Google).
- Без composer-залежностей: `curl` і `openssl`, які є в будь-якій OkayCMS.

**Після встановлення модуль на паузі** — сам нічого в Google не надсилає.

## Вимоги

- PHP 8.5+ з розширеннями `curl`, `openssl`, `json`
- [Форк OkayCMS](https://github.com/devSviat/OkayCMS-Fork) із модулем `OkayCMS/GoogleMerchant`; стокова 4.5.3 не підтримується
- Планувальник OkayCMS у cron: `* * * * * cd {OkayCMS_root} && php ok scheduler:run`
- Акаунт Merchant Center (робочий, не тестовий) з підтвердженим сайтом

## Встановлення

### Варіант 1: Скачування з GitHub

1. Скачайте архів з [останнього релізу](https://github.com/devSviat/MerchantApi-OkayCMS/releases/latest).
2. Розпакуйте його в `{OkayCMS_root}/Okay/Modules/`.

### Варіант 2: Через Git

```bash
cd {OkayCMS_root}/Okay/Modules/Sviat
git clone https://github.com/devSviat/MerchantApi-OkayCMS.git MerchantApi
```

Далі: адмін-панель → Модулі → «Google Merchant API» → «Встановити».

## Налаштування з боку Google

Робиться один раз власником акаунта.

1. **Проєкт Google Cloud.** [console.cloud.google.com](https://console.cloud.google.com) → новий проєкт
   (окремий для магазину) → APIs & Services → Library → **Merchant API** → Enable.
2. **Сервісний акаунт.** IAM & Admin → Service accounts → Create. Ролі в проєкті не потрібні:
   на доступ до Merchant API вони не впливають.
3. **Ключ.** Сервісний акаунт → Keys → Add key → JSON. Файл завантажиться один раз — збережіть його.
4. **Доступ у Merchant Center.** Налаштування → Люди й доступ → додати email сервісного акаунта
   (`…@….iam.gserviceaccount.com`) з роллю **Admin** — вона потрібна для реєстрації (крок 6).
   Акаунт має бути робочим (не тестовим), а сайт у ньому — підтвердженим.
5. **Модуль.** Адмінка → «Google Merchant API» → «Підключення»: завантажте JSON-ключ, вкажіть ID акаунта
   Merchant Center (цифри у правому верхньому куті), адресу сайту, країни показу.
6. **Реєстрація проєкту.** Там само, розділ «Доступ до Google» → «Зареєструвати проєкт» з **вашим** email
   (людини, не сервісного акаунта). Без цього Google відповідає 401 «GCP project … is not registered»
   на всі запити. Цей email отримує роль **API developer**; якщо це ще не користувач акаунта, Google
   надішле запрошення — його треба прийняти. Поки в акаунті немає підтвердженої людини з цією роллю,
   Google відмовляє «should have at least one user with 'API_DEVELOPER' role». Доступ вмикається
   протягом ~5 хвилин; потім «Перевірити зв’язок».
7. Після реєстрації роль сервісного акаунта можна знизити до Standard: реєстрація прив’язана до проєкту.

Документація Google: [реєстрація](https://developers.google.com/merchant/api/guides/quickstart/registration),
[доступ](https://developers.google.com/merchant/api/guides/authorization/access-your-account).

## Налаштування модуля

Над вкладками — кроки готовності: ключ → акаунт і сайт → доступ до Google → мови й джерела →
надсилання ввімкнено. Наступний крок підсвічено, клік веде на потрібну вкладку.

1. «Підключення» → «Перевірити зв’язок»: модуль прочитає джерела даних акаунта.
2. «Мови й джерела»: для кожної мови — передавати чи ні, фід модуля GoogleMerchant (з нього беруться
   категорії й бренди), **мітка фіду**, API-джерело. Мітку модуль підставляє з чинного файлового джерела
   тієї ж мови і попереджає, якщо введена інша. Немає API-джерела — кнопка «Створити API-джерело»;
   способи показу (реклама, безкоштовні оголошення) нове джерело бере з файлового тієї ж мови.
3. За потреби — мітка цінового діапазону: номер мітки й верхні межі, напр. `100, 500, 1000`
   → `0-100`, `101-500`, `501-1000`, `1000+`. Береться ціна зі знижкою, якщо вона є.
4. «Синхронізація» → режим роботи: **Сухий прогін**. Після кількох запусків перегляньте журнал
   (скільки товарів, невалідні, попередження), потім перемкніть на **Надсилати в Google**.

Журнал показує текст відмови Google і підказку, що перевірити. Запуск, який планувальник обірвав за
таймаутом (30 хвилин), позначено «перервано».

За один запуск (раз на 15 хвилин) модуль виконує до 500 операцій на мову; перший повний перехід
каталогу на кілька тисяч товарів займає кілька годин.

## Перехід із XML-фіда

Google визначає товар трьома полями: мова, мітка фіду, ID. Щоб товари перейшли з історією,
API-джерело кожної мови має мати **ту саму мову й мітку**, що й чинне файлове джерело (таблиця
наявних джерел — на вкладці «Мови й джерела»), а ID — ті самі (модуль, як і фід, використовує ID варіанта).

Надсилання товару в API-джерело переносить його туди з файлового. Один товар із двох основних
джерел Google вважає помилкою, тому:

1. Відтворіть правила атрибутів файлових джерел: на API-джерело вони не діють. Мітку цінового
   діапазону — модулем (ті самі межі, що в правилі), решту — вручну. Інакше групи товарів у рекламі,
   побудовані на цих мітках, лишаться порожніми.
2. Сухий прогін: очікувано — вставки за кількістю товарів, 0 видалень, 0 невалідних.
3. **Вимкніть розклад завантаження файлових джерел до живого режиму**: перехід каталогу на кілька
   тисяч товарів триває години, а завантаження файла посеред нього знову дає два джерела одного товару.
4. Режим «Надсилати в Google» (на день переходу можна підняти «Операцій за запуск», напр. до 1500).
   Хід переходу — «Оновити статуси й кількість»: кількість товарів у кожному джерелі.
5. Коли у файлових джерелах 0 товарів — видаліть їх разом із правилами атрибутів.

Відкат: поставте модуль на паузу, у файлових джерелах натисніть «Завантажити зараз» (товари
повернуться туди), і лише потім видаляйте API-джерела. Просто ввімкнути розклад файла, лишивши
товари в API-джерелах, — це знову два основні джерела одного товару.

## Безпека

- Ключ сервісного акаунта зберігається в налаштуваннях модуля, як секрети інших модулів OkayCMS.
  У браузер він не повертається ніколи — видно лише email акаунта й ID ключа; у журнал і лог не пишеться.
- Під час завантаження ключ перевіряється: тип `service_account`, адреса отримання токена — лише
  `https://oauth2.googleapis.com/token`, приватний ключ RSA читається.
- Модуль ходить лише на `oauth2.googleapis.com` і `merchantapi.googleapis.com`: адреси зашиті в код,
  лише HTTPS, без редиректів, з перевіркою сертифіката.
- Окреме право доступу в адмінці; усі дії — POST із CSRF-токеном.
- Скомпрометований ключ: Google Cloud → сервісний акаунт → Keys → видалити; завантажити новий у модуль.
- На копії робочої бази (локальний стенд) тримайте модуль на паузі: у копії лежить і ключ.

## Відомі межі

- Одна країна показу й валюта сайту; кілька країн — не підтримується.
- Дані беруться лише з модуля `OkayCMS/GoogleMerchant` (не з пресетів модуля `OkayCMS/Feeds`).
- Сповіщення Google про зміну статусу (webhook) не використовуються: статуси читаються раз на добу.
- Ліміти квот Google модуль поки не читає: розмір запуску задається вручну.
